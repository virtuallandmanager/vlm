# Room Scan to 3D Set: Implementation Plan (Quest + server + web)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A personal Quest headset uploads its room scan. Virvi turns it into a private, real-scale GLB "room set" with a chosen exterior style. The set can start a new scene in the wizard or become a library asset, and it can be restyled and nudged later on the scene page.

**Architecture:**
- **Shared layout format:** a device-neutral layout type (`RoomScanLayout`, metres, Y up) lives in `vlm-shared`.
- **Quest:** the app maps MRUK into that layout and uploads it through a new AR-pass route.
- **Generator:** a pure server-side generator (`apps/server/src/room-scan/`) builds the GLB with `@gltf-transform/core`, which is already a dependency.
- **Room sets:** a `room_sets` record holds each use of a scan (its options and nudges), and its own GLB is in R2.
- **Wizard and scene page:** both consume room sets through new endpoints.

**Tech Stack:** Fastify, drizzle and Postgres; `@gltf-transform/core` 4.2.1; Next.js with vitest; Kotlin with Meta Spatial SDK MRUK, JUnit 4 and mockwebserver.

**Spec:** `docs/superpowers/specs/2026-10-26-room-scan-design.md`

**Scope:** iPhone/iPad (RoomPlan) capture is a separate later plan, because the iOS app first needs pairing and uploading. This plan's layout format and upload route are what that plan will reuse.

**Naming:** if this runs after the Virvi rename plan (`docs/superpowers/plans/2026-10-25-virvi-rename.md`) has merged, use the renamed packages and paths (`@virvixr/shared`, `org/virvi/ar/...`) wherever this plan says `vlm-shared` or `gg/vlm/spaces`.

## Global Constraints

### Scale and layout

- **Scale:** always 1:1 in metres. The generator never scales a layout to fit a plot.
- **Layout version:** `RoomScanLayout.version = 1`. Units are metres, Y is up, and every room is in one shared frame.

### Privacy and access

- **Scans:** readable only by their owner. Every route answers 404 to anyone else.
- **Room-set assets:** `asset_library_items.is_public = false` with `uploaded_by` = the owner. They never appear in catalog or public listings.
- **Shared headsets can't scan.** Upload is allowed only from an `ar_devices` row with `kind = 'personal'`. A shared device gets 403 `{ error: 'shared_device' }`.
- **No images are stored.** Only the layout JSON is kept, never raw device output.

### Generator defaults

- **Walls:** 0.12 m thick.
- **Ceiling:** off.
- **Furniture blocks:** off.
- **Interior colours:** walls `#E8E6E1`, floor `#B9A68C`.
- **Styles:** `house | storefront | plain | dollhouse`.
- **Thresholds:**
  - Shared-wall merge: parallel within 5°, faces within 0.30 m, and overlap of at least 0.5 m.
  - Door snap: opening centres within 0.25 m.
  - A degenerate wall (shorter than 0.10 m) is dropped.

### Fitting a plot

- **Plot margin:** 0.5 m on every side around the outer wall faces.
- **Plot size:** the smallest square plot of `n×n` parcels (16 m) that holds the footprint plus margin, with `n` no more than `MAX_PLOT_SIDE`.
- **Too big:** 422 `{ error: 'too_big' }`.
- **Triangle budget:** `dclBudget(plotParcels(plot).length).triangles`, from `vlm-shared`.

### Copy (exact)

- **Shared-device refusal:** "Room scans need a personal headset. This one is shared."
- **First public deploy of a set, shown once:** "This World will show your room's layout to anyone who visits."

## Review Focus

1. **An L-shaped or irregular floor outline** (more than 4 corners, angled walls): every wall is built along the outline, with no gaps at corners. Pinned in Task 3.
2. **Bad openings:** a door wider than its wall, or two openings that overlap on one wall. The opening is clamped to the wall, and overlaps merge into one opening. Nothing crashes, and no wall gets a negative width. Pinned in Task 3.
3. **A home bigger than the largest plot:** a clear 422 `too_big` in the wizard and the asset flow, never a silently clipped set. Pinned in Tasks 5 and 6.
4. **A shared or revoked headset trying to upload:** 403 `shared_device` and 401 `device_revoked` respectively, and nothing is stored. Pinned in Task 2.
5. **A scan with zero rooms, or only degenerate walls:** 400 `{ error: 'empty_scan' }` at upload. Pinned in Tasks 1 and 2.

### Task 4: GLB builder and exterior styles

**Files:**
- Create: `apps/server/src/room-scan/build-glb.ts`, plus `apps/server/src/room-scan/styles/{index,house,storefront,plain,dollhouse}.ts`.
- Test: `apps/server/test/room-scan-glb.test.ts`.

**Interfaces:**
- Consumes: Task 3's `wallPieces`, `mergeSharedWalls` and `applyNudges`.
- Produces:

```ts
export type RoomStyle = 'house' | 'storefront' | 'plain' | 'dollhouse'
export interface RoomSetOptions { style: RoomStyle; wallColor: string; floorColor: string; ceiling: boolean; furniture: boolean; signText?: string }
export const DEFAULT_ROOM_SET_OPTIONS: RoomSetOptions // style 'plain', colours from Global Constraints, ceiling false, furniture false
export interface StyleKit { outerMaterial: { name: string; color: string }; roof: 'pitched' | 'flat' | 'none'; outerWallHeight: (ceiling: number) => number; extras: (ctx: StyleContext) => MeshPart[] } // one per style in styles/
export function buildRoomSetGlb(layout: RoomScanLayout, options: RoomSetOptions, nudges?: Array<{ dx: number; dz: number; yaw: number }>): Promise<{ glb: Buffer; triangles: number; bbox: { x: number; y: number; z: number }; offset: { x: number; z: number } }>
```

**What the GLB contains:**
- Wall pieces are extruded to 0.12 m boxes. Inner faces use the `interior-wall` material and outer faces use the style's outer material, on separate primitives so a restyle changes only the exterior materials.
- A floor polygon is triangulated with ear clipping (write a small function, no new dependency) and uses the `floor` material.
- A ceiling is included only when `options.ceiling` is set.
- The roof follows the style kit:
  - **house:** a pitched roof over the footprint's bounding box (25°) and a door canopy at the first door.
  - **storefront:** the outer material on the first door's wall is a glass-tinted material, with an awning box over that door. `signText` is stored as a node name only; real text rendering is out of scope.
  - **plain:** a flat roof slab.
  - **dollhouse:** no roof, and outer walls capped at 1.2 m. Inner walls stay at full height.
- Furniture blocks, when on, are grey boxes per `RoomObject`.
- The whole set is translated so the footprint's minimum corner is at the 0.5 m margin. The applied translation is `offset`.
- Every mesh is flagged with collider metadata the way existing scene models are. Check how the DCL path sets colliders; if it uses a mesh naming convention such as `_collider`, emit those nodes.

- [ ] **Step 1:** Write the tests, reading the output back with the existing `glbStats` (`apps/server/src/catalog/glb-stats.ts`):
  - A 4 × 3 × 2.5 m room in style `plain` has a bounding box of x 4.24 ± 0.01, z 3.24 ± 0.01, and y 2.5 plus the roof thickness (0.1).
  - `ceiling: false` produces no node named `ceiling`.
  - `dollhouse` has no `roof` node.
  - `house` has a `roof` node whose bounding-box top is above 2.5 + 1.0.
  - The triangle count for a 4 × 3 room with one door and one window is under 2,000 for every style.
  - The same layout restyled `plain` → `house` keeps identical `interior-wall` and `floor` primitives (compare vertex counts).
  - `offset` is `{x: 0.56, z: 0.56}` for a room whose outline starts at (0,0): margin 0.5 plus half-thickness 0.06.
  - An L-shaped room builds without throwing, and its floor triangle area equals the outline's area within 1%.
